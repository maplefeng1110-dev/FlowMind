# FlowMind 用户指南

## 1. 概述

FlowMind 是一个 AI Native RPA（机器人流程自动化）编排系统，通过自然语言对话的方式帮助用户完成各种自动化任务。

**核心优势**：
- 自然语言驱动的流程自动化
- 无需学习复杂的 RPA 工具
- 本地执行，数据安全
- 支持多种 RPA 插件
- 多用户权限管理

## 2. 系统要求

### 2.1 硬件要求

- 处理器：Intel i5 或同等性能
- 内存：4GB 以上
- 存储：至少 5GB 可用空间
- 网络：稳定的互联网连接

### 2.2 软件要求

- **操作系统**：
  - Windows 10/11（推荐，用于桌面 RPA）
  - macOS 10.15+
  - Linux（Ubuntu 20.04+）

- **Python**：Python 3.11+

- **依赖库**：所有依赖库将通过 `requirements.txt` 自动安装

## 3. 安装与配置

### 3.1 下载与安装

1. 克隆或下载项目代码到本地
2. 进入项目目录

### 3.2 环境配置

#### 3.2.1 创建虚拟环境

```bash
# Windows
py -3.11 -m venv .venv
.\.venv\Scripts\activate

# macOS/Linux
python3.11 -m venv .venv
source .venv/bin/activate
```

#### 3.2.2 安装依赖

```bash
# 所有系统
pip install -r requirements.txt
```

#### 3.2.3 配置环境变量

1. 复制 `.env.example` 为 `.env`：

```bash
# Windows
copy .env.example .env
copy agent\.env.example agent\.env

# macOS/Linux
cp .env.example .env
cp agent/.env.example agent/.env
```

2. 编辑根目录 `.env` 文件，配置以下关键参数：

```bash
# AI 提供商（至少配置一个）
DEEPSEEK_API_KEY=your_deepseek_api_key
# ARK_API_KEY=your_ark_api_key  # 可选，火山引擎

# 服务器配置（默认即可）
REGISTRY_API_URL=http://127.0.0.1:8000

# 管理员账号（必填）
FLOWMIND_ADMIN_USERNAME=admin
FLOWMIND_ADMIN_PASSWORD=your_password

# 安全密钥（必填）
SECRET_KEY=your_secret_key_here

```

3. 编辑 `agent/.env` 文件，配置 Agent 侧参数：

```bash
REGISTRY_URL=ws://127.0.0.1:8000/ws
MACHINE_ID=local-dev-machine
# AGENT_HEARTBEAT_INTERVAL_SEC=10
# AGENT_ADMIN_ENABLED=true
# AGENT_ADMIN_HOST=127.0.0.1
# AGENT_ADMIN_PORT=8765
# AGENT_ADMIN_PUBLIC_URL=https://agent-a.example.com
# AGENT_ADMIN_TOKEN=replace-with-a-random-token
# Web 根目录 .env 可选：
# AGENT_ADMIN_TOKEN_STORE_PATH=data/agent_admin_tokens.json
# AGENT_ADMIN_API_TOKENS_JSON='{"machine-a":"token-a","machine-b":"token-b"}'
# 建议运行态 token store 使用 chmod 600，并补齐 rotated_at 元数据
# OCR_API_URL=your_ocr_api_url
# OCR_API_TIMEOUT=15
# SMTP_SERVER=smtp.example.com
# SMTP_PORT=587
# SMTP_USER=your_email@example.com
# SMTP_PASSWORD=your_email_password
```

**获取 API 密钥**：
- DeepSeek：[https://www.deepseek.com/](https://www.deepseek.com/)
- 火山引擎：[https://console.volcengine.com/ark/](https://console.volcengine.com/ark/)

## 4. 启动与访问

### 4.1 启动系统

#### 4.1.1 方式一：使用启动脚本（推荐）

```bash
# 终端 1：启动 Registry + Web
# Windows
.\.venv\Scripts\python.exe run_stable.py

# macOS/Linux
./.venv/bin/python run_stable.py

# 终端 2：单独启动 Agent
# Windows
.\.venv\Scripts\python.exe run_agent.py

# macOS/Linux
./.venv/bin/python run_agent.py
```

#### 4.1.2 方式二：分别启动服务

```bash
# 启动 Registry（终端 1）
./.venv/bin/python -m uvicorn registry.main:app --host 127.0.0.1 --port 8000

# 启动 Agent（终端 2）
./.venv/bin/python -m agent.main

# 启动 Client（终端 3）
./.venv/bin/python -m client.web_server
```

仅运行 `run_stable.py` 时不会自动启动 Agent，因此如果工具面板为空或任务一直等待，请先确认 `run_agent.py` 或 `-m agent.main` 已单独启动。
如果 Agent 无法连接 Registry，也请确认 `agent/.env` 中的 `REGISTRY_URL` 和 `MACHINE_ID` 是否配置正确。

### 4.2 访问系统

1. 打开浏览器，访问：http://127.0.0.1:5173
2. 使用配置的管理员账号登录

## 6. 使用流程

### 6.1 基础使用

1. 登录系统
2. 在对话区输入指令（如："识别这张发票"）
3. 如果需要上传文件，点击上传按钮
4. 系统会自动识别意图并调用相应的 RPA 插件
5. 查看工具执行结果

### 6.2 使用示例

#### 6.2.1 发票识别

**用户消息**："识别这张发票"

**操作过程**：
1. 点击上传按钮，选择发票图片
2. 系统识别意图，调用 `invoice_ocr` 插件
3. 显示工具正在执行
4. 返回识别结果

**结果示例**：
```
成功识别发票！

发票信息：
- 发票类型：增值税普通发票
- 发票号码：12345678
- 开票日期：2024年01月01日
- 金额：¥100.00
```

#### 6.2.2 发送邮件

**用户消息**："给张三发送邮件，主题是'会议通知'，内容是'明天上午10点在会议室开会'"

**操作过程**：
1. 系统识别意图，调用 `send_email` 插件
2. 执行邮件发送
3. 返回发送结果

**结果示例**：
```
邮件发送成功！

收件人：张三 <zhangsan@example.com>
主题：会议通知
内容：明天上午10点在会议室开会
```

### 6.3 企业级对话编排体验

当请求涉及多个自动化步骤时，FlowMind 会在同一条助手消息里展示：

- **运行时计划**：系统理解成了什么、准备按什么顺序执行
- **工具调用轨迹**：当前调了哪些工具、参数是什么、结果摘要是什么
- **约束告警**：是否缺关键参数、是否需要确认、是否触发路径范围限制
- **恢复建议**：失败后应该补参数、等待后台任务，还是从当前节点继续

典型示例：

- “把这些发票识别后汇总到 Excel，再发邮件给财务”
- 系统会先生成临时计划，再依次调用 `invoice_ocr`、`excel_processor`、`send_email`
- 如果邮件发送属于高风险副作用操作，系统会检查是否已经得到用户明确指令
- 如果 Excel 步骤失败，消息里会保留已完成步骤和恢复建议，而不是整条链路都丢失

## 7. 可用插件

### 7.1 已实现的插件

| 插件名称 | 功能描述 | 输入要求 | 使用场景 |
|----------|----------|----------|----------|
| **invoice_ocr** | 发票 OCR 识别 | 发票图片或 PDF 文件 | 财务报销、发票录入 |
| **send_email** | 发送邮件 | 收件人、主题、内容 | 通知、报告发送 |
| **web_query** | 搜索、页面摘要、结构化抽取、批量抓取、选择器提取 | `mode` + 查询词或 URL | 信息收集、网页抽取、轻量爬取 |
| **excel_processor** | 汇总、筛选、生成报表、读取区间、写单元格、追加行、按列聚合 | `operation` + Excel 文件路径 | 数据清洗、报表生成、批量修订 |
| **word_processor** | 摘要、格式化、替换文本、模板填充、大纲提取、表格提取 | `operation` + Word 文件路径 | 文档整理、模板生成、内容提取 |

### 7.2 插件使用限制

- **权限控制**：不同角色的用户可以使用不同的插件
- **可用性**：插件需要对应的 Agent 在线才能使用
- **参数验证**：插件会验证输入参数的有效性
- **执行环境**：大多数插件默认依赖本地文件路径或网络连通性，更适合内网或桌面环境下的 Agent
- **风险确认**：像发送邮件这类存在外部副作用的插件，系统会在运行时检查确认条件
- **范围约束**：涉及文件路径的插件默认更适合处理上传文件或授权目录中的文件

## 9. 任务管理

### 9.1 查看任务

1. 点击"任务管理"
2. 查看所有正在执行和已完成的任务
3. 点击任务查看详细信息

### 9.2 任务状态

- **pending**：任务待执行
- **running**：任务正在执行
- **success**：任务成功完成
- **error**：任务执行失败
- **timeout**：任务执行超时

### 9.3 任务重试

对于失败的任务，可以点击"重试"按钮重新执行。

### 9.4 常用任务

当一段多步骤对话成功跑通后，系统会提示是否保存为**常用任务**：

1. 在助手消息底部点击“保存为常用任务”
2. 输入一个容易识别的名称
3. 任务会出现在左侧“常用任务”区域
4. 下次点击即可把原始 prompt 预填回输入框，快速复用

这不是固定流程编辑器，而是把成功的自由对话沉淀成可复用入口。

### 9.5 定时调度中心

当前版本已经内建了**定时调度中心**，入口在顶部时钟按钮。

你可以这样使用：

1. 点击顶部“调度中心”按钮
2. 选择一条常用任务，或直接填写要定时执行的 prompt
3. 选择调度类型：
   - 一次性
   - 固定间隔
   - 每日定时
4. 选择模型提供商、执行时间和时区
5. 保存后，计划会出现在右侧列表
6. 计划每次执行后，下面的“最近执行记录”会显示状态、会话和错误摘要

当前调度中心的几个特点：

- 计划会沿用**当前账号的插件权限**
- 执行结果会继续写入对话和任务中心
- 计划可以启用、暂停、编辑和删除

### 9.6 统一导出中心

当前版本已经内建了**统一导出中心**，入口在顶部下载按钮。

支持导出的对象包括：

- 当前对话
- 任务中心
- 常用任务
- 调度计划
- 调度执行记录

支持的标准格式：

- `JSON`
- `CSV`
- `Markdown`（当前对话）

## 12. 常见问题与故障排除

### 12.1 系统无法启动

**问题**：执行启动命令后没有响应

**解决方案**：
1. 检查 Python 版本是否符合要求（3.11+）
2. 检查依赖是否正确安装
3. 检查端口是否被占用（默认端口：8000, 5173）
4. 查看日志文件（`logs/` 目录下的 log 文件）

### 12.2 插件无法调用

**问题**：系统识别到意图但无法调用插件

**解决方案**：
1. 检查 Agent 是否在线
2. 检查插件是否已启用
3. 检查用户权限是否包含该插件
4. 查看 Agent 日志（`logs/agent.log`）

### 12.3 工具执行失败

**问题**：插件执行失败

**解决方案**：
1. 检查输入参数是否正确
2. 检查文件是否存在且格式正确
3. 查看插件日志（如 `logs/invoice_ocr.log`）
4. 尝试重新执行

### 12.4 邮件发送失败

**问题**：`send_email` 插件执行失败

**解决方案**：
1. 检查 SMTP 配置是否正确
2. 检查网络连接
3. 检查邮箱账号是否可用
4. 查看 `logs/send_email.log`

### 12.5 发票识别失败

**问题**：`invoice_ocr` 插件执行失败

**解决方案**：
1. 检查图片质量（清晰度、光照）
2. 检查图片格式是否支持（JPG、PNG、PDF）
3. 检查 OCR API 配置是否正确
4. 查看 `logs/invoice_ocr.log`

## 13. 安全注意事项

### 13.1 数据安全

- 所有数据在本地处理，不发送到外部服务器
- 上传的文件保存在本地（`data/uploads/` 目录）
- 定期清理不再需要的文件

### 13.2 权限管理

- 严格控制用户权限
- 定期审查用户账号
- 及时删除不再使用的账号

### 13.3 系统安全

- 定期更新依赖库
- 定期备份数据库（`data/registry.db`）
- 配置防火墙规则
- 不要在生产环境中使用默认密码

## 16. 当前优先改进方向

从用户和实施视角看，当前最值得继续补强的方向主要有：

1. **可视化流程编排**：把“聊天里一次触发多步工具”升级成真正可配置、可复用、可版本化的流程。
2. **调度与导出增强**：当前已有中心入口，下一步更值得补失败重试、事件触发、Excel/PDF 和脱敏下载。
3. **真实浏览器与移动端体验验证**：当前界面已经可用，但仍建议继续补 Chrome / Safari / 移动端专项验证。
4. **生产运维能力**：补齐 Docker、反向代理、TLS、备份恢复、监控告警等上线配套能力。
5. **插件实战化**：继续增加真实 Excel / Word / 网页样本的覆盖，降低边界格式导致的失败率。

- 发送邮件到支持邮箱
- 加入用户交流群

### 18.2 开发人员

- 查看项目代码：[GitHub 仓库](https://github.com/your/repository)
- 提交 Pull Request
- 参与开发讨论
